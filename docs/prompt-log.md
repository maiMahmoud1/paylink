## Summary

The PayLink team used AI during requirements analysis, software architecture, UML design, backend implementation, DevOps, and testing. AI-generated outputs were reviewed against the Student Brief and the project's actual requirements before being accepted or committed.

Several entries required human correction rather than direct acceptance. In particular:

1. The initial architecture recommendation was Microservices, which was considered unnecessarily complex for the four-student project. The prompt was refined and a Modular Monolith using Layered Architecture was selected.
2. The initial payment state diagram was too simple and did not cover required PayLink scenarios such as funds holding, Unknown status, timeouts, retries, and refunds.
3. The generated use-case diagram contained inappropriate `extend` relationships, which were removed after the team inspected the rendered diagram.
4. The refund sequence was reviewed and corrected to address duplicate refunds, Unknown-status protection, support approval, and audit logging.
5. The CI workflow initially failed when running `pytest` directly, so the test command was changed to `python -m pytest`.
